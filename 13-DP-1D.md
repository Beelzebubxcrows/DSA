# 13 · Dynamic Programming: 1D

> **Prereqs:** 10 · **Time:** 5–6 days

## When to use

- The problem asks for the **number of ways**, the **min or max**, or **is it possible**.
- Choices made at each step lead to **overlapping subproblems** (the plain recursion tree recomputes the same states).
- The problem has **optimal substructure**: the best answer is built from the best answers to smaller subproblems.

## Framework (use it on every DP problem)

1. **State**: what does `dp[i]` mean? Write it out in words.
2. **Transition**: how do you get `dp[i]` from smaller states?
3. **Base cases**.
4. **Answer**: is it `dp[n]`, or `max(dp)`?
5. **Order**: fill the table so each state's dependencies are computed first.
6. **Optimise space**: if `dp[i]` only depends on `dp[i-1]` and `dp[i-2]`, keep two variables.

Start with recursion plus memoization (top-down), then convert it to a table (bottom-up) if needed.

## Common 1D shapes

| Shape | Transition | Examples |
|-------|-----------|----------|
| Fibonacci-like | `dp[i] = dp[i-1] + dp[i-2]` | Climbing Stairs, Decode Ways |
| Take or skip | `dp[i] = max(dp[i-1], dp[i-2] + a[i])` | House Robber |
| Unbounded knapsack | `dp[x] = min(dp[x - c] + 1)` over each coin c | Coin Change |
| 0/1 knapsack | iterate x **backwards** | Partition Equal Subset Sum |
| LIS | `dp[i] = 1 + max(dp[j])` for j < i with `a[j] < a[i]` | LIS, O(n log n) with patience sorting |
| Track max and min | keep both the current max and min | Max Product Subarray |
| Expand around centre | not a table, O(n²) | Palindromic substrings |

## Templates

```java
// Top-down (Integer[] memo, so null means "not computed yet")
Integer[] memo = new Integer[n];
int f(int i) {
    if (i >= n) return 0;
    if (memo[i] != null) return memo[i];
    return memo[i] = Math.max(f(i + 1), nums[i] + f(i + 2));
}

// Bottom-up, O(1) space (House Robber)
int prev2 = 0, prev1 = 0;
for (int x : nums) {
    int cur = Math.max(prev1, prev2 + x);
    prev2 = prev1;
    prev1 = cur;
}

// Coin change (min coins)
int[] dp = new int[amount + 1];
Arrays.fill(dp, amount + 1);   // "infinity" that can't overflow when you add 1
dp[0] = 0;
for (int x = 1; x <= amount; x++)
    for (int c : coins)
        if (c <= x) dp[x] = Math.min(dp[x], dp[x - c] + 1);
return dp[amount] > amount ? -1 : dp[amount];

// 0/1 knapsack boolean
boolean[] dp = new boolean[target + 1];
dp[0] = true;
for (int x : nums)
    for (int s = target; s >= x; s--)
        dp[s] |= dp[s - x];
```

## Pitfalls

- Not defining the state clearly enough. This causes most DP bugs.
- 0/1 knapsack: iterating forwards, which lets you reuse the same item more than once.
- Using `Integer.MAX_VALUE` as "impossible": `MAX_VALUE + 1` overflows to a negative number. Use a safe sentinel such as `amount + 1`, and convert it to `-1` at the end.
